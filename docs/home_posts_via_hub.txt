================================================================================
BLUE ATMOSPHERE — POSTS HOME VIA HUB — ALGORITHME V3
================================================================================

STATUT
------

Règle produit et technique de référence pour les publications Home.
Cette version remplace toute ancienne règle indiquant qu'un post Home crée une
delivery individuelle par ami. Il n'y a jamais N lignes delivery pour N amis.

================================================================================
1. PÉRIMÈTRE
================================================================================

Cette règle concerne les publications Home et leurs réponses publiques.

Ne sont pas concernées :

- cui-to-cui et réponses privées : trajet direct vers une personne ;
- envoi vers une branche : trajet direct vers la position immuable de la
  branche, puis diffusion V3 propre à la branche ;
- échos et recommandations : ce ne sont pas des messages personnels.

================================================================================
2. PRINCIPE
================================================================================

Un post Home a deux phases distinctes :

    auteur -> hub le plus proche -> diffusion Home

Une réponse publique à une note Home hérite obligatoirement de ce contexte :
elle effectue elle aussi auteur -> hub proche, puis une diffusion Home. Le type
REPLY ne constitue jamais à lui seul une destination physique.

1. L'auteur envoie un seul message au hub géographiquement le plus proche de
   sa position au moment de l'envoi.
2. À l'arrivée, le hub crée une diffusion logique vers les amis éligibles.
3. Chaque ami est autorisé à voir le message lorsque le backend constate que
   son arrivée calculée est atteinte, ou lorsqu'il l'avait déjà reçu.

Le hub peut aussi être une gateway, mais une gateway n'a aucun rôle spécial
pour un post Home. Le choix est toujours le hub le plus proche.

================================================================================
3. CAS PIGEON
================================================================================

    auteur -- pigeon direct --> hub le plus proche -- diffusion --> amis

Le premier trajet est un vrai trajet fixe auteur -> hub : distance, vitesse,
heure de départ et arrivée sont enregistrées une seule fois. Le pigeon personnel
est rendu dès son arrivée au hub.

Pour la diffusion :

- le hub est seulement un relais GPS ;
- aucun tri, horaire, dimanche, jour férié ou routage gateway ne s'applique ;
- le délai potentiel d'un ami est calculé de hub -> dernière position connue de
  cet ami, avec le moteur pigeon ;
- la vitesse déterministe de ce calcul utilise une seed incluant message_id et
  recipient_user_id ;
- aucune delivery utilisateur n'est créée.

================================================================================
4. CAS LETTRE / POSTE
================================================================================

    auteur -- poste --> hub le plus proche -- diffusion --> amis

Le premier trajet auteur -> hub suit la logistique postale normale. À son
arrivée, le slot postal de l'auteur est rendu.

Pour la diffusion :

- le hub traite ensuite le post comme une origine postale ;
- pour un ami non encore reçu, le backend calcule hub -> dernière position
  connue de cet ami avec les règles postales complètes ;
- hubs, gateways, horaires, fermetures, week-ends et jours fériés s'appliquent
  à ce calcul ;
- aucune copie de contenu et aucune delivery utilisateur ne sont stockées.

================================================================================
5. DONNÉES ET VISIBILITÉ V3
================================================================================

Un post Home correspond à :

    1 message de contenu
    1 action d'envoi de l'auteur
    1 delivery physique initiale auteur -> hub
    1 broadcast Home
    0..n fragments bitmap temporaires

Le broadcast contient notamment :

- message_id ;
- hub d'origine de la diffusion ;
- distribution_started_at (arrivée au hub) ;
- méthode ;
- settled_at, calculé avec une borne maximale de propagation configurée.

Les fragments bitmap contiennent un bit par ami stable de la relation Home.
Un bit à 1 signifie : « le backend a déjà autorisé ce compte à recevoir ce
message ». Ce n'est pas un accusé de lecture et ce n'est pas une delivery.

À l'ouverture de la Home, le backend :

1. récupère les posts des amis avec un broadcast arrivé au hub ;
2. vérifie que l'amitié concernée existait à distribution_started_at ;
3. si le bit du lecteur est à 1, retourne immédiatement le message ;
4. sinon calcule l'arrivée vers sa dernière position connue ;
5. si l'arrivée est atteinte, pose le bit atomiquement puis retourne le
   message ; sinon, ne retourne rien.

Le front-end ne décide jamais de l'accès ; il affiche seulement le résultat
du backend, par exemple « Un pigeon vient d'arriver ».

================================================================================
6. LOCALISATION DU DESTINATAIRE
================================================================================

La dernière position connue se trouve dans la ligne du compte utilisateur.

- La localisation est demandée lors de l'inscription.
- Quand l'application est ouverte au premier plan, elle ne redemande une
  position que si location_checked_at date d'au moins 24 heures.
- Il n'y a ni GPS continu ni suivi en arrière-plan.
- location_checked_at est un horodatage serveur indépendant du jeton de
  connexion.

Le calcul pour un ami non reçu utilise donc cette dernière position connue.
Si une position plus récente ferait reculer l'arrivée mais que le bit a déjà
été posé, le message reste visible : une réception validée ne disparaît pas.

================================================================================
7. FIN DE LA FENÊTRE DE PROPAGATION
================================================================================

Chaque méthode possède une durée maximale de propagation configurée. Lorsque
settled_at est atteint :

- les fragments bitmap temporaires du broadcast peuvent être supprimés ;
- messages et relation d'amitié historique restent conservés ;
- le post est considéré comme arrivé pour tous les amis qui étaient éligibles
  au début de la diffusion ;
- un nouvel ami ne récupère pas rétroactivement les anciens posts Home.

La borne doit être volontairement supérieure au pire délai mondial de la
méthode ; sa valeur est une constante de gameplay versionnée, pas une estimation
faite à partir de la position actuelle d'un ami.

================================================================================
8. RÈGLES À NE PAS CASSER
================================================================================

1. Un post Home ne crée jamais une delivery par ami.
2. Le contenu n'est enregistré qu'une fois dans messages.
3. Le premier trajet jusqu'au hub est fixe ; la diffusion vers un ami non reçu
   est évaluée au moment de sa lecture par le backend.
4. Un bit « reçu » est posé atomiquement et ne repasse jamais à 0.
5. Le pigeon personnel / slot postal de l'auteur n'est pas bloqué jusqu'à
   l'ami le plus lointain.
6. Les données exactes de position ne sont jamais renvoyées à un autre client.
