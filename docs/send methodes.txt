VERSION :
1.0

OBJECTIF :

Créer dans l'application deux méthodes artificielles d'envoi de messages :

1. ENVOI PAR OISEAU
2. ENVOI PAR POSTE

Les messages ne sont pas reçus instantanément.

Chaque méthode possède son propre système de calcul de délai.

L'objectif est de donner à l'utilisateur l'impression que son message
voyage réellement entre lui et le destinataire.

Le système doit rester :

- simple à coder
- déterministe
- facilement équilibrable
- compréhensible
- compatible avec n'importe quelle position GPS dans le monde
- suffisamment crédible sans reproduire la réalité exacte

======================================================================
01. PHILOSOPHIE GÉNÉRALE
======================================================================

Les deux méthodes doivent fonctionner de manière volontairement opposée.


OISEAU :

Le message voyage directement de A vers B.

Le principal facteur du délai est :

LA DISTANCE


POSTE :

Le message voyage à travers une infrastructure.

Le principal facteur du délai est :

LA LOGISTIQUE


L'oiseau doit être très efficace sur une petite distance,
mais extrêmement lent sur une très longue distance.

La poste doit être relativement lente même sur une petite distance,
mais très efficace sur les grandes distances grâce aux transports rapides.


Exemple conceptuel :

Lille → Londres

Oiseau :
rapide

Poste :
plus lente à cause du traitement


Lille → Tokyo

Oiseau :
plusieurs semaines

Poste :
quelques jours

======================================================================
03. CALCUL HAVERSINE
======================================================================

Toutes les distances géographiques sont calculées avec Haversine.

Cette formule permet de calculer la distance approximative
entre deux coordonnées GPS sur la surface de la Terre.


ENTRÉE :

latitude A
longitude A

latitude B
longitude B


SORTIE :

distance en kilomètres


PSEUDOCODE :

distanceKm(pointA, pointB)


EXEMPLE JAVASCRIPT / TYPESCRIPT :

function distanceKm(a, b) {

    const R = 6371;

    const toRad = deg =>
        deg * Math.PI / 180;

    const dLat =
        toRad(b.lat - a.lat);

    const dLon =
        toRad(b.lon - a.lon);

    const lat1 =
        toRad(a.lat);

    const lat2 =
        toRad(b.lat);

    const hav =
        Math.sin(dLat / 2) ** 2
        +
        Math.cos(lat1)
        *
        Math.cos(lat2)
        *
        Math.sin(dLon / 2) ** 2;

    return 2
        * R
        * Math.atan2(
            Math.sqrt(hav),
            Math.sqrt(1 - hav)
        );
}

======================================================================
05. PRINCIPE DE L'OISEAU
======================================================================

Le système OISEAU ignore complètement :

- les hubs
- les régions
- les pays
- les frontières
- les gateways
- les centres de tri
- les horaires d'ouverture
- les week-ends
- les jours fériés


Le trajet est simplement :

EXPÉDITEUR

↓

OISEAU

↓

DESTINATAIRE


Le délai dépend principalement de :

distance GPS

× facteur de détour

÷ vitesse

+ repos


======================================================================
06. PARAMÈTRES DU ROUGE-GORGE
======================================================================

Pour la première version :

OISEAU :

Rouge-gorge


ID :

ROBIN


VITESSE MOYENNE :

45 km/h


HEURES DE VOL PAR JOUR :

12 heures


HEURES DE REPOS PAR JOUR :

12 heures


FACTEUR DE DÉTOUR :

1.10


VARIATION DE VITESSE :

± 8 %


Cela signifie que la vitesse effective peut être comprise entre :

41.4 km/h

et

48.6 km/h


Cette variation est choisie une seule fois au moment de l'envoi.


DATA :

ROBIN = {

    id: "ROBIN",

    speedKmH: 45,

    flightHoursPerDay: 12,

    restHoursPerDay: 12,

    routeFactor: 1.10,

    speedVariance: 0.08
}


======================================================================
07. CALCUL DE DISTANCE EFFECTIVE
======================================================================

La distance GPS n'est pas utilisée directement.

L'oiseau ne suit jamais une ligne absolument parfaite.

On ajoute donc :

10 %


FORMULE :

DISTANCE_EFFECTIVE
=
DISTANCE_GPS × 1.10


EXEMPLE :

distance GPS :

9500 km


distance effective :

9500 × 1.10

=

10450 km


CODE :

const effectiveDistance =
    gpsDistance * 1.10;


======================================================================
08. CALCUL DE LA VITESSE
======================================================================

La vitesse doit varier légèrement entre les voyages.

Vitesse moyenne :

45 km/h


Variation :

± 8 %


FORMULE :

MIN_SPEED
=
45 × 0.92

MAX_SPEED
=
45 × 1.08


Puis choisir une valeur déterministe entre les deux.


EXEMPLE :

vitesse obtenue :

46.7 km/h


CODE CONCEPTUEL :

const minSpeed =
    45 * (1 - 0.08);

const maxSpeed =
    45 * (1 + 0.08);

const effectiveSpeed =
    seededRandomBetween(
        messageId,
        minSpeed,
        maxSpeed
    );


======================================================================
09. CALCUL DU TEMPS DE VOL
======================================================================

FORMULE :

FLIGHT_HOURS
=
DISTANCE_EFFECTIVE
/
EFFECTIVE_SPEED


Exemple :

10450 km

÷

45 km/h

=

232.2 heures de vol


CODE :

const flightHours =
    effectiveDistance
    /
    effectiveSpeed;


======================================================================
10. GESTION DES JOURNÉES ET DU REPOS
======================================================================

L'oiseau vole :

12 heures par jour


Puis se repose :

12 heures


Un moyen simple de calculer :

FULL_FLIGHT_DAYS
=
floor(
    FLIGHT_HOURS
    /
    12
)


REMAINING_FLIGHT_HOURS
=
FLIGHT_HOURS
%
12


Exemple :

232 heures de vol


232 / 12

=

19,3 journées de vol


Cela représente environ :

environ 19 à 20 jours calendaires


Une méthode plus précise peut simuler les journées.


PSEUDOCODE :

remainingFlight = flightHours
currentTime = sentAt

while remainingFlight > 0:

    flightToday =
        min(12, remainingFlight)

    currentTime += flightToday

    remainingFlight -= flightToday

    if remainingFlight > 0:
        currentTime += 12 heures de repos


VERSION SIMPLIFIÉE :

deliveryHours =
    flightHours
    *
    (24 / 12)


Donc :

deliveryHours
=
flightHours × 2


Attention :

Pour le dernier jour,
il est préférable de ne pas ajouter inutilement
les 12 heures de repos finales.


VERSION PLUS PRÉCISE :

fullDays =
    floor(flightHours / 12)

remaining =
    flightHours % 12


SI remaining = 0 :

calendarHours =
    (fullDays - 1) * 24
    + 12


SINON :

calendarHours =
    fullDays * 24
    + remaining


======================================================================
11. VARIATION ALÉATOIRE DÉTERMINISTE
======================================================================

Il ne faut PAS utiliser un random différent
à chaque recalcul.

Sinon :

un message pourrait arriver lundi,
puis mardi après un refresh.


Toutes les valeurs aléatoires doivent utiliser une seed.


Seed recommandée :

messageId


Exemple :

MESSAGE :

MSG_A7291


Cette seed doit toujours produire :

vitesse :

44.73 km/h


et jamais une autre vitesse.


PSEUDOCODE :

random =
    seededRandom(messageId)


speed =
    lerp(
        minSpeed,
        maxSpeed,
        random
    )


Une fonction simple possible :

function hashString(str) {

    let hash = 2166136261;

    for (const char of str) {

        hash ^= char.charCodeAt(0);

        hash =
            Math.imul(
                hash,
                16777619
            );
    }

    return hash >>> 0;
}


Puis transformer le hash en valeur :

0 → 1


======================================================================
12. POSITION DE L'OISEAU
======================================================================

L'oiseau peut être affiché sur une carte.

Il n'est pas nécessaire de calculer une vraie trajectoire aérienne.


On calcule :

progression =
temps écoulé effectif
/
durée totale


Puis :

latitude actuelle
=
lat départ
+
(lat destination - lat départ)
× progression


longitude actuelle
=
lon départ
+
(lon destination - lon départ)
× progression


EXEMPLE CODE :

const progress =
    elapsedMs / totalMs;

const currentLat =
    sender.lat
    +
    (receiver.lat - sender.lat)
    * progress;

const currentLon =
    sender.lon
    +
    (receiver.lon - sender.lon)
    * progress;


IMPORTANT :

Cette interpolation est correcte pour une représentation visuelle simple.

Pour les très longues distances,
une interpolation géodésique peut être ajoutée plus tard.

22. TROUVER LE HUB LE PLUS PROCHE
======================================================================

L'application ne dessine aucune frontière.

Pour un utilisateur :

1. prendre ses coordonnées

2. calculer sa distance vers chacun des 40 hubs

3. garder le hub avec la distance minimale


PSEUDOCODE :

nearestHub = null
bestDistance = infinity

for hub in hubs:

    distance =
        Haversine(
            user,
            hub
        )

    if distance < bestDistance:

        nearestHub = hub

        bestDistance = distance

function findNearestHub(location, hubs) {

    let nearest = null;

    let minDistance = Infinity;

    for (const hub of hubs) {

        const d =
            distanceKm(
                location,
                hub
            );

        if (d < minDistance) {

            minDistance = d;

            nearest = hub;
        }
    }

    return {
        hub: nearest,
        distanceKm: minDistance
    };
}

function calculateBirdDelivery(
    sender,
    receiver,
    messageId,
    sentAt
):

    gpsDistance =
        Haversine(
            sender,
            receiver
        )

    effectiveDistance =
        gpsDistance
        * 1.10

    random =
        seededRandom(
            messageId
            + "_BIRD_SPEED"
        )

    speed =
        randomBetween(
            41.4,
            48.6,
            random
        )

    flightHours =
        effectiveDistance
        /
        speed

    fullDays =
        floor(
            flightHours
            /
            12
        )

    remainingHours =
        flightHours
        %
        12

    if remainingHours == 0:

        calendarHours =
            max(
                12,
                (fullDays - 1) * 24 + 12
            )

    else:

        calendarHours =
            fullDays * 24
            + remainingHours

    deliveryAt =
        sentAt
        + calendarHours

    return {
        distance,
        effectiveDistance,
        speed,
        flightHours,
        calendarHours,
        deliveryAt
    }

function calculatePostDelivery(
    sender,
    receiver,
    messageId,
    sentAt
):

    origin =
        findNearestHub(
            sender
        )

    destination =
        findNearestHub(
            receiver
        )


    if origin.region
       ==
       destination.region:

        route =
            [
                origin,
                destination
            ]

    else:

        originGateway =

            origin.gateway
            ?
            origin
            :
            findNearestGateway(
                origin
            )


        destinationGateway =

            destination.gateway
            ?
            destination
            :
            findNearestGateway(
                destination
            )


        route =
            [
                origin,
                originGateway,
                destinationGateway,
                destination
            ]


    route =
        removeAdjacentDuplicates(
            route
        )


    timeline = []


    currentTime =
        sentAt


    collectionDelay =
        deterministicRandom(
            messageId
            + "_COLLECTION",
            2,
            6
        )


    currentTime += collectionDelay


    timeline.add(
        COLLECTION
    )


    distanceToOrigin =
        Haversine(
            sender,
            origin
        )


    localTransport =
        max(
            distanceToOrigin
            /
            65,
            2
        )


    currentTime += localTransport


    timeline.add(
        LOCAL_TRANSPORT
    )


    for each hub in route:


        currentTime =
            moveToNextOperatingTime(
                hub,
                currentTime
            )


        processingTime =

            hub.gateway
            ?
            deterministicRandom(
                messageId
                + hub.id,
                8,
                16
            )
            :
            deterministicRandom(
                messageId
                + hub.id,
                5,
                12
            )


        currentTime =
            consumeWorkingHours(
                hub,
                currentTime,
                processingTime
            )


        timeline.add(
            HUB_PROCESSING
        )


        if hub is not final hub:


            nextHub =
                route[next]


            distance =
                Haversine(
                    hub,
                    nextHub
                )


            transportMode =
                getTransportMode(
                    hub,
                    nextHub,
                    distance
                )


            frequency =
                getDepartureFrequency(
                    transportMode,
                    sameRegion
                )


            departureTime =
                getNextDeparture(
                    currentTime,
                    frequency
                )


            timeline.add(
                WAITING_DEPARTURE
            )


            travelHours =
                distance
                /
                transportMode.speed


            currentTime =
                departureTime
                +
                travelHours


            timeline.add(
                INTER_HUB_TRANSPORT
            )


    distanceToReceiver =
        Haversine(
            destination,
            receiver
        )


    finalTransport =
        max(
            distanceToReceiver
            /
            65,
            2
        )


    currentTime +=
        finalTransport


    finalDelay =
        deterministicRandom(
            messageId
            + "_FINAL",
            2,
            6
        )


    currentTime +=
        finalDelay


    timeline.add(
        FINAL_DELIVERY
    )


    return {

        originHub:
            origin.id,

        destinationHub:
            destination.id,

        route:
            route.map(
                h => h.id
            ),

        timeline,

        estimatedDeliveryAt:
            currentTime
    }

48. RÈGLES FONDAMENTALES À NE PAS CASSER
======================================================================

RÈGLE 1

L'oiseau ne passe JAMAIS par les hubs pour un trajet direct classique.

Exception V3 : pour un post Home, le seul trajet physique de l'auteur est
auteur -> hub Home le plus proche. Après cette arrivée, le hub est un relais
GPS immédiat et la diffusion utilise le broadcast V3, sans trajet postal.


RÈGLE 2

La poste utilise TOUJOURS le hub géographiquement le plus proche.


RÈGLE 3

Il existe exactement 40 hubs dans cette version.


RÈGLE 4

Il existe exactement 10 gateways.


RÈGLE 5

Une liaison entre deux régions doit passer par des gateways.


RÈGLE 6

Une liaison dans une même région ne nécessite pas de gateway.


RÈGLE 7

Si un hub local est déjà une gateway,
ne pas ajouter une gateway supplémentaire.


RÈGLE 8

Les doublons dans la route sont supprimés.


RÈGLE 9

Tous les calculs géographiques utilisent Haversine.


RÈGLE 10

Tous les randoms importants utilisent une seed basée sur messageId.
Pour une vitesse pigeon, inclure aussi targetId : messageId + targetId.


RÈGLE 11

Une fois un voyage physique généré,
il ne change plus.

Exception V3 : le calcul d'un broadcast vers un utilisateur dont le bit reçu
vaut 0 est évalué à la lecture avec sa dernière position connue. Dès que le
backend pose le bit, cette réception est définitivement acquise.

======================================================================
49. INTÉGRATION OBLIGATOIRE — DIFFUSION V3
======================================================================

Ce moteur sert aussi au broadcast V3. Cette règle prévaut sur toute ancienne
interprétation qui créerait une delivery par membre de Home ou de branche.

TRAJETS PHYSIQUES FIXES
-----------------------

- cui-to-cui : expéditeur -> destinataire ;
- branche : expéditeur -> coordonnées immuables de la branche ;
- Home : expéditeur -> hub le plus proche.

Ces trajets sont calculés et enregistrés une fois à l'envoi selon les règles
normales du pigeon ou de la poste.

Pour le cui-to-cui, la delivery directe détaillée est temporaire. Son heure
d'arrivée est copiée à l'envoi dans messages.available_at ; après l'arrivée, le
backend autorise uniquement recipient_user_id quand available_at <= now. La
delivery peut donc être purgée de façon différée sans supprimer le message ni
son droit de lecture. Cette règle ne s'applique pas à un broadcast : un direct
ne possède ni bitmap ni état « arrivé pour toute l'audience ».

DIFFUSION APRÈS ARRIVÉE
-----------------------

Quand le message atteint une branche ou le hub Home, créer un broadcast. Le
broadcast fournit origine, méthode, distribution_started_at et settled_at, mais
ne crée pas de delivery utilisateur.

Lorsqu'un destinataire éligible ouvre la Home ou la branche, le BACKEND calcule
le trajet virtuel depuis cette origine vers sa dernière position connue :

- PIGEON : distance directe ; le hub Home est seulement un relais GPS. La seed
  de vitesse est messageId + recipientUserId, pas messageId seul ;
- POSTE : appliquer la chaîne postale complète depuis l'origine (hub ou
  branche) jusqu'à cette position.

Si now atteint l'arrivée calculée, le backend pose atomiquement son bit reçu et
retourne le message. Si le bit vaut déjà 1, le message reste retourné sans
recalcul. Le bit n'est pas un accusé de lecture.

La position est mise à jour au premier plan au plus une fois toutes les 24 h,
sans GPS continu. settled_at est une borne mondiale configurée par méthode ; à
son arrivée, les bitmaps temporaires peuvent être purgés et les personnes qui
étaient éligibles à distribution_started_at ont accès au message.
